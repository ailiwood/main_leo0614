## 发现的问题（必须修复后才能进入架构升级）

### P0-1：GitHub 缺少 data 代码文件

当前 `data/` 目录被 .gitignore 的 `data/` 规则整体排除，导致：
- `data/strong_sequence_dataset.py` 未进入 Git
- `data/sequence_dataset.py` 未进入 Git
- `data/dataset.py` 未进入 Git

**修复**：.gitignore 必须区分 data/*.py（进入 Git）和 data/features*/（不进入 Git）。

### P0-2：strict_trainer.evaluate 阶段疑似未传全模态 mask

audit 发现 evaluate() 方法中：
```python
out = self.model(txt, aud, vis, text_mask=tm)
```
仅传入 text_mask，audio_mask 和 vision_mask 为 None。

对于 T>1 序列特征，audio/vision 有不同长度，mask 必须正确传入。

**修复**：evaluate 中传入三模态 mask：
```python
out = self.model(txt, aud, vis, text_mask=tm, audio_mask=am, vision_mask=vm)
```

### P0-3：check_val API 仍保留 test_loader 参数

当前签名：`check_val(epoch, val_loader, test_loader)`  
但 test_loader 在函数体内未被使用，却保留了接口。这增加了 test leakage 风险。

**修复**：改为 `check_val(epoch, val_loader)`，或至少注释 test_loader must not be used。

### P0-4：strong sequence 真实配置未固化

C0 在 strong sequence 上的训练配置散落在临时 Python 脚本中，无独立 yaml 配置。

**修复**：新增 `configs/models/ours_c0_strong_sequence.yaml`。
